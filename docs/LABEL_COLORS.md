# Label Organization Guide

This guide documents every label used in this repository, grouped by category, so that issues and pull requests can be organized and triaged consistently.

## Label Categories

| Label Name | Category | Description |
|------------|----------|-------------|
| bug | Issue Type | Something isn't working |
| enhancement | Issue Type | New feature or request |
| question | Issue Type | Further information is requested |
| duplicate | Issue Type | This issue or pull request already exists |
| invalid | Issue Type | This doesn't seem right |
| documentation | Area | Improvements or additions to documentation |
| accessibility | Area | Barrier affecting people with disabilities |
| good first issue | Status | Good for newcomers |
| help wanted | Status | Extra attention is needed |
| wontfix | Status | This will not be worked on |

## Usage Guidelines

- **Issue Type** labels (`bug`, `enhancement`, `question`, `duplicate`, `invalid`) describe the nature of an issue or pull request and should be applied when the item is first triaged. Use `bug` for defects, `enhancement` for feature requests, `question` for information requests, `duplicate` when the same item already exists, and `invalid` when the report doesn't apply.
- **Area** labels (`documentation`, `accessibility`) identify which part of the project the work touches. Apply `documentation` to changes affecting docs or guides, and `accessibility` to issues affecting people with disabilities.
- **Status** labels (`good first issue`, `help wanted`, `wontfix`) communicate the current state or next action for an item. Use `good first issue` to flag beginner-friendly work, `help wanted` to invite outside contributions, and `wontfix` to close out items that will not be addressed.

Consistent use of these categories improves visual organization across the issue tracker and makes triage faster for maintainers and contributors alike.
